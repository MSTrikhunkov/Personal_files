# Бэкпорты безопасности Django 4.2.30

Подготовлено 2026-09-16 для предоставленного `4.2.30.tar.gz`.
SHA-256 исходного архива: `a6a919d9a64d54db5f1396259fc6bb0dc9a17a55ffb382f57394b63bf364b77b`.

**6 отдельных патчей, каждый для одной CVE.** Ещё 8 CVE уже исправлены в архиве; 2 неприменимы. Полная матрица с доказательствами: [APPLICABILITY.md](APPLICABILITY.md). Сокращённый идентификатор `CVE-53877` интерпретирован как `CVE-2026-53877`. `CVE-2025-5783` не подменён молча: он относится к другому продукту; похожий `CVE-2025-57833` также проверен.

Патчи созданы настоящими `git commit` и `git format-patch`, содержат изменения кода, регрессионные тесты и необходимую документацию. История подготовки находится в `../django-4.2.30`, исходная точка — тег `baseline-4.2.30`, ветка — `security-backports`. Upstream-коммиты указаны в сообщениях патчей и [SOURCES.md](SOURCES.md).

## Порядок применения

Машиночитаемый порядок — [series](series), по одному имени файла на строку:

1. CVE-2026-6873 — пространства имён подписанных cookies.
2. CVE-2026-8404 — регистр директивы private.
3. CVE-2026-48587 — пробелы в Vary и необходимая для 4.2 проверка Vary: *.
4. CVE-2026-48588 — запрет кэширования Set-Cookie + Vary: Cookie.
5. CVE-2026-53877 — корректный размер байтового буфера GDALRaster.
6. CVE-2026-15830 — ограничение коллекций геометрии перед вызовом GEOS.

Применять все шесть в указанном порядке к **чистому исходному архиву**, а не повторно к уже исправленному `../django-4.2.30`. Пример для нового рабочего каталога (настроенный Git author/committer нужен для commit/am):

```sh
tar -xzf /path/to/4.2.30.tar.gz
cd django-4.2.30
git init
git add .
git commit -m 'Baseline Django 4.2.30'
PATCH_DIR=/absolute/path/to/patches
while IFS= read -r patch_name; do
    git am "$PATCH_DIR/$patch_name" || exit 1
done < "$PATCH_DIR/series"
```

Для сборочной системы, использующей обычные unified diff, из корня исходников:

```sh
PATCH_DIR=/absolute/path/to/patches
while IFS= read -r patch_name; do
    patch -p1 < "$PATCH_DIR/$patch_name" || exit 1
done < "$PATCH_DIR/series"
```

`SHA256SUMS` проверяет целостность файлов в этой директории (`shasum -a 256 -c SHA256SUMS`). После установки новой сборки необходимо очистить ранее заполненный page cache: правки предотвращают новые небезопасные записи, но не удаляют старые записи кэша.

## Совместимость и границы исправлений

Версия пакета, зависимости и существующие позиционные аргументы не изменены. Код совместим с грамматикой Python 3.8; фактические тесты выполнены на Python 3.9.6. Не перенесены посторонние изменения Django 5.2. В частности, патч CVE-2026-8404 не переносит сопутствующее изменение поведения `no-cache`/`no-store` из upstream-коммита.

**CVE-2026-6873 имеет неизбежный компромисс совместимости.** Как в upstream, новые cookies подписываются однозначно, а старые по умолчанию принимаются (`SIGNED_COOKIE_LEGACY_SALT_FALLBACK = True`). Пока fallback включён, старые подписи по-прежнему могут использовать коллизию `key + salt`: это не полное устранение риска для legacy-cookies. Для полного отключения старых неоднозначных подписей приложение должно установить:

```python
SIGNED_COOKIE_LEGACY_SALT_FALLBACK = False
```

Это действие намеренно **не включено по умолчанию**: оно инвалидирует старые подписанные cookies. Старые непатченные процессы не умеют проверять новый формат, поэтому смешанный кластер/откат и сторонние потребители, самостоятельно собирающие salt как `key + salt`, требуют согласованной миграции. Одновременно сохранить полную совместимость старого формата и запретить его коллизии невозможно. Настройки приложений не изменялись.

**CVE-2026-15830:** добавлен необязательный `max_geom_collections`, по умолчанию 198. Для WKT это глубина, для WKB/hex-WKB — консервативный подсчёт возможных заголовков коллекций, включая совпадения внутри данных. Очень широкие или необычно закодированные WKB могут теперь отклоняться. Лимит настраивается на GEOSGeometry, модельном и form-поле; явный `None` отключает его, уменьшая защиту. Уже сохранённая геометрия при чтении через штатные DB-конвертеры не ограничивается, GeoJSON обрабатывается прежним способом через GDAL. Дефолтный аргумент не попадает в миграции; ранее существующие миграции не переписаны. Дополнительно исправлены две ошибки upstream-патча: учёт big-endian hex-WKB и передача явного None в form-поле.

Cache-патчи прекращают повторную выдачу ответов, помеченных private, Vary: * или Set-Cookie + Vary: Cookie; это необходимое изменение небезопасного поведения. Остальные ответы сохраняют прежнее кэширование. Исправление GDAL меняет только передаваемую длину буфера.

Абсолютная совместимость произвольных внешних компонентов не утверждается: перечисленные изменения формата и допустимых входов являются частью исправлений безопасности. Проверенные сценарии и ограничения среды перечислены в [TESTING.md](TESTING.md).
