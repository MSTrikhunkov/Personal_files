# Исправления безопасности Nova 31.0.0

Исходный архив: `31.0.0.tar.gz`.
SHA-256: `09e96ce8356dd8430f10750b072b3ad57df5984c5c6ca47353ec6b7eef92a5a9`.

Обе уязвимости применимы к исходному коду этого архива. Оснований
объявлять какую-либо из них неприменимой нет. Патчи переносят изменения
официальной ветки `stable/2025.1` без изменения содержания diff, включая
регрессионные тесты. Обновление Nova целиком не требуется.

## CVE-2026-24708

Официальное уведомление: https://security.openstack.org/ossa/OSSA-2026-002.html

Исправление: https://review.opendev.org/977103

Upstream commit: `992646e49b4b4d96f3258dc154d6f00a43d18d01`.
Исходный master commit: `3eba22ff09c81a61750fbb4882e5f1f01a20fdf5`.
Исправленная версия серии 31: 31.2.1.

В исходном `nova/virt/disk/api.py`, функция `extend()` вызывает
`qemu-img resize` без `-f`. Backend `Flat.resize_image()` передаёт сюда
`LocalFileImage(self.path, self.driver_format)`. Пользователь гостя может
записать заголовок QCOW2 в raw-диск, после чего при resize qemu-img ошибочно
интерпретирует содержимое как иной формат и может повредить файлы хоста.
Условие эксплуатации — использование Flat (обычно `use_cow_images=False`).
Конфигурация конкретного развёртывания не предоставлена; наличие других
backend не делает уязвимый код пакета неприменимым.

Патч передаёт `-f raw` или `-f qcow2` согласно доверенным метаданным
образа; ploop сохраняет прежний путь через `ploop_resize`. Иные форматы
отклоняются до изменяющего диск вызова qemu-img.

Совместимость: сигнатуры функций и требования к пакетам не меняются.
В исходной 31.0.0 `nova/virt/image/model.py:ALL_FORMATS` уже ограничен
raw, qcow2, ploop; обычное создание `LocalFileImage(..., 'vmdk')` уже
завершается `InvalidImageFormat`. Новая проверка не исключает ни один
формат из этого списка. Апстрим отдельно предупреждает о прекращении
случайно работавшего resize иных форматов при обходе ограничений модели.

Граница исправления из upstream: содержимое `disk.info` должно оставаться
корректным. Удаление/повреждение этого файла и последующее определение
формата по недоверенному диску — отдельный сценарий, который данный
upstream-патч не устраняет. Не следует удалять `disk.info` для работающих ВМ.
В официальном уведомлении исправлена ранняя опечатка CVE-2026-24709;
правильный идентификатор — CVE-2026-24708.

## CVE-2026-46448

Официальное уведомление: https://security.openstack.org/ossa/OSSA-2026-022.html

Исправление: https://review.opendev.org/993604

Upstream commit: `355edcbbc66233328a9b29014cf69e081f6d663e`.
Исходный master commit: `9666894b46db4c2c66824f1b6e89584de3ab17b2`.
Исправленная версия серии 31: 31.3.1.

В исходном `nova/compute/api.py`, `API.create()` без фильтрации передаёт
пользовательские scheduler hints в `build_filter_properties()`.
`nova/scheduler/utils.py:request_is_rebuild()` доверяет внутреннему
`_nova_check_type=['rebuild']`. В результате create может пройти как
внутренняя проверка rebuild, обходя распределение ресурсов Placement
и ограничения планирования.

Патч в `API.create()` удаляет все ключи с префиксом `_nova` до передачи
планировщику. Остальные hints сохраняются; запрос не отклоняется.
Внутренний код настоящего rebuild, который самостоятельно добавляет
`_nova_check_type`, не меняется.

Совместимость: API microversions, схемы запросов, RPC, объекты Nova,
схема БД и взаимодействие с Placement/Neutron/Cinder/Glance не меняются.
Не требуется обновление этих компонентов. Меняется только возможность
задавать служебные hints извне — это намеренное закрытие уязвимости.

## Применение

В чистом git-дереве, содержащем распакованную Nova 31.0.0:

```sh
git am /absolute/path/security-patches/0001-*.patch \
       /absolute/path/security-patches/0002-*.patch
```

Порядок указан также в `series`. Патчи созданы отдельными `git commit`
и экспортированы `git format-patch`; исходные авторы сохранены.
Оригинальные патчи Gerrit и метаданные сохранены в `upstream/` для аудита.
Результаты и ограничения тестирования приведены в `VALIDATION.md`.
