## Выполненные регрессионные проверки

```sh
python3 security-patches/verify_backports.py nova-31.0.0
```

Проверочный скрипт компилирует настоящие тела `API.create()`, `extend()` и
классы модели образа из указанного дерева через AST. Тела функций не
переписываются. Зависимости, не участвующие в проверяемой логике, заменены
тестовыми объектами; классы исключений — локальным тестовым исключением.
Это изолированные проверки, а не запуск штатного unit/integration suite Nova.

До изменения production-кода: **14 тестов, 7 ожидаемых падений**
(`portable-before.log`). После: **14/14 успешно** (`portable-after.log`).
Повторно на свежей распаковке после `git am`: **14/14 успешно**.
Использован Python 3.9.6; синтаксис четырёх изменённых Python-файлов также
проверен через `ast.parse`.

Покрыто: удаление `_nova*` с list/string значениями, весь зарезервированный
префикс, сохранение обычных/неизвестных hints, `None` и пустой словарь,
отсутствие мутации входного словаря; явные raw/qcow2 форматы, прежняя ветка
ploop, запрет неизвестного формата до запуска qemu-img, исходный запрет VMDK
моделью образа, прежнее поведение для нелокального образа и отсутствия роста.

Один тест вызывает настоящий `qemu-img` 11.1.1: в отдельном временном
каталоге создаётся безвредный QCOW2-файл без backing/external data files,
который передаётся `extend()` как raw-диск с заголовком, контролируемым гостем.
После патча меняется физический размер raw-файла, а первые 512 байт остаются
прежними. До патча эта проверка падает. Внешние файлы хоста тест не затрагивает.

## Ограничения среды и оставшиеся проверки

В `.venv` установлены зависимости из `requirements.txt` и
`test-requirements.txt` с официальными upper constraints серии 2025.1.
Версии зафиксированы в `test-environment-freeze.txt`, процесс установки —
в `dependency-install.log`. Файлы зависимостей самой Nova не изменены.

Попытка штатного запуска под Python 3.12.14:

```sh
.venv/bin/python -m unittest \
  nova.tests.unit.virt.disk.test_api \
  nova.tests.unit.compute.test_api.ComputeAPIUnitTestCase.test_create_strips_internal_scheduler_hints
```

Остановилась ещё на импорте `oslo_privsep.capabilities`: macOS не содержит
Linux-символ `prctl` (`tests-before.log`). Docker daemon недоступен.
Штатные upstream-тесты включены в патчи, но их успешный запуск здесь
**не подтверждён**. Полный тестовый набор и интеграция с работающими
Nova/Placement/libvirt не проверялись. Проверка с реальным qemu-img выполнена
на указанной локальной версии, а не на неизвестной версии целевого хоста.

Для завершающей проверки на Linux с окружением Nova 2025.1 рекомендуется:

```sh
stestr run 'nova.tests.unit.virt.disk.test_api|nova.tests.unit.compute.test_api|nova.tests.unit.virt.libvirt.test_imagebackend|nova.tests.unit.scheduler.test_utils'
```

Статический анализ совместимости и границы upstream-исправлений описаны
в `README.md`; они не заменяют проверку конкретного развёртывания.
