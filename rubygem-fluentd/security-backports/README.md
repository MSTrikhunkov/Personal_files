# Backport безопасности Fluentd 1.16.2

Обе CVE применимы к предоставленному тарболу. Подготовлены два отдельных
коммита и патча `git format-patch`; обоснований неприменимости нет.

| CVE | Решение | Подробности |
| --- | --- | --- |
| CVE-2026-44160 | Порционная распаковка и настраиваемый лимит 256 MiB | [Анализ](CVE-2026-44160.md) |
| CVE-2026-44025 | Серверное разрешение доступа к instance variables | [Анализ](CVE-2026-44025.md) |

В `series` указан порядок применения. `upstream/` содержит оригиналы PR для
сравнения; они не входят в серию backport. Все новые тесты включены в патчи.

## Исходник и история

SHA-256 `v1.16.2.tar.gz`:
`f737fb92b955288fc935a07cfa72ec2e4953206cbdf69922e7e6757c6cea2634`.

Рабочий Git: `../fluentd-1.16.2`, исходный tag: `pristine-1.16.2`.

- `de30d5b`: CVE-2026-44160.
- `6ce3a0e`: CVE-2026-44025.

Патчи созданы командой:

```sh
git format-patch --output-directory ../security-backports pristine-1.16.2..HEAD
```

## Применение

В рабочем Git-дереве исходного Fluentd 1.16.2:

```sh
git am /path/to/security-backports/0001-*.patch /path/to/security-backports/0002-*.patch
```

Если исходники только из тарбола, сначала распаковать и создать исходный коммит:

```sh
tar -xzf v1.16.2.tar.gz
cd fluentd-1.16.2
git init
git add .
git commit -m 'Import Fluentd 1.16.2'
git am ../security-backports/0001-*.patch ../security-backports/0002-*.patch
```

## Совместимость

Не изменены версия, требования Ruby, gemspec, зависимости, форматы Forward и
дисковых буферов. Старые позиционные вызовы и необязательные аргументы сохранены.
Настройки `include_config`/`include_retry` остаются `true`; маскированный config,
retry-метрики, обычные JSON/LTSV ответы и pretty JSON сохранены.

Точное сохранение уязвимого поведения невозможно: сообщения, распаковывающиеся
выше заданного лимита, отклоняются; произвольные внутренние переменные больше
не выдаются без явного `include_debug_info true`. Для легитимных больших сообщений
лимит можно увеличить. Opt-in debug возвращает риск утечки, как в upstream.
Эти необходимые security-изменения нельзя считать полной поведенческой
идентичностью исходной версии.

Для monitor_agent намеренно сохранены старые config/retry defaults вместо
несовместимого переключения обоих на false из upstream. Поэтому полная политика
минимизации раскрываемых данных 1.19.3 не переносится: сторонние плагины обязаны
объявлять секретные config-параметры с `secret: true`. Подробности и остаточные
риски указаны в анализе CVE-2026-44025.

## Валидация

Среда: macOS arm64, системная Ruby 2.6.10; зависимости установлены из RubyGems
в `../.test-gems`, без изменения системных gems и gemspec Fluentd.
Версии записаны в `validation/gems.txt`, сведения о среде — `validation/ruby.txt`.
Ruby 2.4 и Linux в этом окружении не тестировались; новые конструкции языка
не требуют повышения заявленного минимального Ruby 2.4.

Выполнены:

- Red-проверки исходного кода: HTTP принимает payload сверх лимита; monitor_agent
  раскрывает секрет через debug/with_ivars и допускает обход include_config false.
- Регрессии обходов через MemoryChunk#open и копирование отложенного потока.
- Расширенный набор затронутых компонентов: 423 теста / 1708 assertions,
  без ошибок; затем дополнительный retry-тест: 8 тестов / 14 assertions,
  без ошибок. Логи `validation/full.log` и `validation/44025-green.log`.
- `git diff --check` без замечаний.
- Оба патча применены через `git am` на свежую распаковку исходного тарбола,
  без конфликтов. Tree SHA совпал с рабочим деревом:
  `aac13e76e87864a952ef4a597f62d757da5e3b1f`.
  Лог: `validation/git-am.log`.
- Повтор полного целевого набора после `git am`: **424 теста / 1711 assertions,
  0 failures, 0 errors**. Итоговый лог: `validation/reapplied.log`.

Скрипт `./security-backports/run-tests.sh` запускает целевые suites; аргументом
можно передать другую директорию исходников. Это локальный harness с GEM_HOME
из `../.test-gems`; для сборочной среды дистрибутива следует установить её
штатные тестовые зависимости. Тестам нужны локальные TCP/UDP-сокеты.
Полный набор всех тестов Fluentd не запускался.
