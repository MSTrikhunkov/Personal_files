# CVE-2026-54770: backport для WebOb 1.8.9

## Вывод

Уязвимость **применима** к предоставленному архиву `1.8.9.tar.gz`.
SHA-256 архива: `b941fbb3f1ad77841090c6a856b4d43c2e85b32abad0746a4c09853c1197b0ca`.

В `Response._make_location_absolute()` проверка схемы и `//` выполняется
до вызова стандартного `urljoin`. В актуальных Python этот вызов удаляет
начальные C0-символы и пробелы, превращая, например, ` //evil.example/path`
в ссылку на внешний хост. `_HTTPMove` самостоятельно вызывает небезопасный
`urljoin`; `Request.relative_url()` также использует его. На исходном коде
под Python 3.12.14 воспроизведены 11 отказов регрессионных проверок.
Эксплуатация требует влияния атакующего на адрес перенаправления приложения.
Один только номер версии Python недостаточен для вывода о неприменимости:
преобразования URL переносились также в обновления старых веток Python,
а прямой путь `_HTTPMove` затронут независимо от удаления начальных пробелов.

## Исправление

Основа — официальное исправление WebOb:

- https://github.com/Pylons/webob/security/advisories/GHSA-6hx8-3wjj-gr8g
- https://github.com/Pylons/webob/commit/ff89560643fb252751b4db8806a283b5377f1f07
- Регрессионные тесты: https://github.com/Pylons/webob/commit/54c1133c79e48940776a272f4500530e1cc3232a

Перенесён собственный resolver URI из upstream, используемый в Response и
Request.relative_url; HTTP redirect exceptions направлены через общую
нормализацию Response. Дополнительно перенесено удаление TAB/CR/LF перед
проверками Location (предшествующее исправление CVE-2026-44889, отсутствующее
в 1.8.9). Версия пакета, зависимости и сигнатуры существующих публичных
методов не изменены; код не требует новых возможностей синтаксиса Python.

Отличие от upstream: конец регулярного выражения схемы закреплён через `\Z`
вместо `$`. Последний в Python допускает конечный LF; поэтому
`Request.relative_url('https\n://evil.example/path')` мог распознавать
недопустимую схему. Добавлен тест, сначала воспроизводивший этот дефект.

Обычные относительные пути, query/fragment, явные абсолютные URL,
`to_application`, отсутствие Location и `add_slash` проверяются тестами.
Явные абсолютные внешние URL остаются разрешены: патч не заменяет проверку
допустимых redirect destinations на уровне приложения.
Небезопасное прежнее поведение намеренно меняется: протокол-относительные
Location у HTTP-исключений больше не перенаправляют на другой хост,
а управляющие символы не должны превращать относительный путь в абсолютный.

Resolver upstream следует RFC 3986. Для пограничных входов есть отличия
от urllib: сохраняются пустые query/fragment (`?`, `#`) и повторные `/`
в относительном пути. Это не изменение API, но приложения, зависящие именно
от таких преобразований urllib, требуют отдельной интеграционной проверки.
Произвольные сторонние компоненты и Python 2.7/3.4–3.8 здесь не запускались;
полную совместимость с неуказанным окружением невозможно подтвердить.

## Проверки

- Python 3.9.6 / pytest 8.4.2: **3054 passed, 9 skipped, 1 xfailed**.
- Python 3.12.14 / pytest 8.4.2: **3053 passed, 9 skipped, 1 xfailed,
  1 failed**. Единственная ошибка — `test_client_cookies`, присутствующая
  и до патча: исходный тест создаёт заголовок `X-Crazy` с CR/LF, который
  актуальная `wsgiref.headers.Headers` запрещает. Этот сторонний дефект
  тестовой совместимости не скрыт и не исправлялся данным патчем.
- Исходная регрессионная выборка: 11 failed, 5 passed; после исправления
  соответствующие проверки проходят.
- Дополнительно проверены все начальные C0-символы и пробел, HTTP redirect
  classes, оба режима Request.relative_url и обычные перенаправления.
- Полные журналы и версии зависимостей: `../logs/`.

Воспроизводимый запуск из каталога исходников с pytest в окружении:

```sh
PYTHONPATH=src python -m pytest -q
```

Тестам HTTP-клиента необходимо разрешение открывать локальный TCP-порт.
Предупреждения об устаревших API исходной версии сохранены в журналах.

## Применение

Основной файл патча лежит в этой папке и создан командой
`git format-patch -1 HEAD --stdout` после отдельного `git commit`.
Репозиторий с исходным и исправляющим коммитами: `../webob-1.8.9/`.
`../sources/` содержит справочные upstream-патчи; отдельно применять их не нужно.

Из корня свежераспакованного WebOb 1.8.9:

```sh
patch -p1 --dry-run < /path/to/CVE-2026-54770/delivery/python-webob-1.8.9-CVE-2026-54770.patch
patch -p1 < /path/to/CVE-2026-54770/delivery/python-webob-1.8.9-CVE-2026-54770.patch
```

Для исходников, уже находящихся в Git:

```sh
git am /path/to/CVE-2026-54770/delivery/python-webob-1.8.9-CVE-2026-54770.patch
```

Исправляющий коммит: `3122829`. Патч проверен через `git apply --check`,
применён к новой распаковке исходного архива; исходники и тесты совпадают
с исправленным репозиторием. Полный повторный запуск после применения:
**3054 passed, 9 skipped, 1 xfailed** на Python 3.9.6.
Контрольная сумма патча: `../SHA256SUMS`.
