# Security backports для OpenSearch Dashboards 2.14.0

Дата проверки: 2026-09-16. Исходный архив: `2.14.0.tar.gz`.

SHA-256 архива:

```text
3113c0c831864be82aa9f1174593ba341c127f90513dabca23cde5d06fcb3078
```

В комплекте четыре последовательных патча, backport-исправления для шести запрошенных идентификаторов и обоснования неприменимости двух остальных. Исправляются исходные версии зависимостей, а не подменяются номера версий. `package.json`, `yarn.lock`, Node.js 18.19.0, версия Dashboards, форматы CommonJS/ESM, конфигурация и API Dashboards не меняются.

Применимость на уровне библиотеки не равнозначна доказанной удалённой эксплуатации конкретного маршрута Dashboards. Например, nanoid здесь приходит через Mocha и PostCSS, а js-yaml используется в том числе при чтении локальной конфигурации. Эти компоненты всё равно исправляются, включая инструменты сборки. Отсутствие удалённого PoC не использовалось как основание неприменимости.

### Уточнение CVE-2026-73086

CNA описывает переполнение при `size |= 0` и значении 2147483648. В точных 3.3.2/3.3.3 из данного lock-файла стоит `size -= 0`: именно положительный ввод 2147483648 завершается `RangeError`, и этот путь переполнения не воспроизводится. Однако отрицательный `-2147483648` после первого вызова `nanoid()` повреждает `poolOffset`, и последующие вызовы возвращают одинаковую строку `uuuuuuuuuuuuuuuuuuuuu`. Поэтому библиотека не объявлена безопасной только из-за отличия арифметики. Патч проверяет неотрицательное целое безопасное число до любых изменений пула и не вводит ограничение длины 1024. Тестируются также длина 2048 и допустимое строковое число `'10'`. Подробности: `evidence/nanoid-pool.log`.

## Порядок применения

Патчи предназначены для **исходного** дерева из предоставленного архива. Все четыре применяются до установки/сборки. Не применять `dependency-diffs/` к корню Dashboards: это вспомогательные diff библиотек для просмотра и сопровождения; установщик уже выполняет эти изменения.

Пример для чистой распаковки, когда `patches/` лежит рядом с `2.14.0.tar.gz`:

```sh
set -eu
PATCH_DIR="$(pwd)/patches"
mkdir -p patched-source
tar -xzf 2.14.0.tar.gz -C patched-source
cd patched-source/OpenSearch-Dashboards-2.14.0
while IFS= read -r item; do
  patch -p1 --dry-run < "$PATCH_DIR/$item"
  patch -p1 < "$PATCH_DIR/$item"
done < "$PATCH_DIR/series"
```

Последовательность:

1. `0001-js-yaml-omap-and-backport-hooks.patch` — установщик, его подключения, исправления всех трёх js-yaml.
2. `0002-lodash-unset-omit-prototype-guard.patch` — lodash и lodash-es.
3. `0003-nanoid-size-and-random-pool.patch` — три CVE nanoid.
4. `0004-decode-uri-component-bounded-decoder.patch` — URI-декодер.

Далее используйте штатные Node.js 18.19.0 и Yarn 1.22.19 и обычную процедуру сборки версии 2.14.0, например:

```sh
yarn osd bootstrap
node scripts/security_backports/apply.cjs .
node scripts/security_backports/apply.cjs . --check
# Далее штатная build-команда для целевых платформ вашего процесса сборки.
```

Повторный явный вызов после bootstrap намеренный и безопасный: он проверяет окончательное дерево всех workspaces. При обычном Yarn install hook запускается из `scripts/postinstall.js`. Если установка выполнялась с `--ignore-scripts`, явный вызов обязателен **до любых сборок и запуска**.

Production-сборка заново устанавливает зависимости. Поэтому патч 0001 дополнительно вызывает установщик в `src/dev/build/tasks/install_dependencies_task.ts` после `project.installDependencies()`, до сборки плагинов и упаковки. Изменение только developer `node_modules` было бы недостаточным. Готовые старые frontend bundles необходимо пересобрать; правка установленных JS-файлов не исправляет уже собранные bundles.

Проверка распакованного нового production-артефакта, используя скрипт из patched source:

```sh
node /absolute/path/to/patched-source/scripts/security_backports/apply.cjs \
  /absolute/path/to/unpacked-distribution --check
```

Укажите реальный корень source, содержащий `scripts/`, в первой строке команды.

### Как работает установщик

- Находит целевые пакеты в `node_modules`, включая вложенные и workspace-копии внутри выбранного корня.
- Проверяет точную версию и SHA-256 каждого изменяемого файла; несовпадение останавливает выполнение, а не пропускается молча.
- До записи проверяет весь найденный набор. Для каждого файла известны исходный и исправленный SHA-256.
- Повторное выполнение не изменяет уже исправленные файлы; `--check` ничего не записывает и требует, чтобы исправления уже присутствовали.
- Записывает через временный файл и rename, чтобы не перезаписать hard-linked Yarn cache. Не изменяет внешние symlink/workspace-деревья за пределами переданного корня.
- Останавливается и при неизвестной версии целевого пакета. Для дополнительных плагинов/зависимостей, отсутствующих в исходном архиве, нужна отдельная оценка.

После переустановки зависимостей hook/явный вызов должен выполняться снова. Только установка обычных npm-пакетов из неизменённого lock-файла, без установщика, возвращает исходный уязвимый код. Версионный сканер может продолжать выдавать предупреждения: подтверждением backport служат diff и проверка хешей, а не фиктивное увеличение версии.

## Совместимость и намеренные изменения поведения

Major/minor версии не обновляются; js-yaml 3.x сохраняет `safeLoad`, nanoid 3.x сохраняет CJS/ESM, decode-uri-component сохраняет синхронный `module.exports` и обработку `+`. Не переносится ESM-only пакет decode-uri-component 0.5.0 целиком. Minified файлы изменяются точечно, без замены неминифицированными bundles.

Обычные сценарии API сохранены в пределах выполненных тестов. Исправления намеренно меняют небезопасные/некорректные случаи:

- lodash отказывает в удалении по путям с `__proto__` или цепочкой `constructor.prototype`, в том числе с вложенными массивами вместо строковых сегментов. Это касается и объектов с одноимёнными собственными полями. Обычные пути, числовые и Symbol-сегменты сохраняются.
- nanoid не повреждает пул отрицательным, дробным, бесконечным размером или NaN; нулевой/отрицательный размер затронутых генераторов завершается вместо зависания.
- Новый fallback URI-декодера не повторяет старую потерю уже декодированного `%` при смешанном повреждённом UTF-8. Например, `%FF%FF%FF%25` даёт `%FF%FF%FF%` вместо `%FF%FF%FF`. Также устранена зависимость результата от того, какой повторяющийся фрагмент встретился раньше: `%41%%41%20%ab` корректно декодирует пробел и внутри второго фрагмента. Повреждённые строки могут поэтому отличаться от старого fallback. Если внешняя интеграция зависит от таких ошибочных результатов, её необходимо проверить отдельно.

Нет изменений формата saved objects, протокола OpenSearch, HTTP-маршрутов или пользовательской конфигурации. Полный запуск Dashboards и его плагинов не выполнялся; абсолютная совместимость со всеми сторонними плагинами этим набором тестов не доказана.

## Проверки и воспроизведение

Проверено на Node.js **18.19.0**, macOS arm64:

- применение каждого diff к исходным файлам архива без fuzz/offset, обратное применение и повторное применение;
- неизменность `package.json`, `yarn.lock`, `.node-version`;
- SHA-512 всех восьми npm-архивов совпадает с исходным `yarn.lock`;
- 42 регрессионные проверки: на исходных библиотеках 39 ожидаемых отказов, после патчей 0;
- 10 000 корректных URI полностью совпадают с исходной реализацией; отдельно выполнены 10 000 сравнений повреждённых строк: 20 намеренных fallback-различий отражены в отчёте; экспортируемые имена API неизменны;
- вложенные копии, игнорирование package.json тестовых fixtures вне границ пакета, workspace symlink cycle, защита hard-linked cache, идемпотентность, read-only проверка, отказ до записи при неожиданном содержимом и неизвестной версии;
- выполнение реального production task body с подменённой только установкой пакетов: свежие зависимости исправляются после установки.

Полная установка всех зависимостей Dashboards, TypeScript/lint всего проекта, браузерные функциональные тесты, запуск с OpenSearch и release-сборка **не выполнялись**. Native entry nanoid исправлен по тому же шаблону async-кода, но среда Expo/React Native отдельно не запускалась. Эти ограничения нельзя подменять заявлением о полной сертификации совместимости.

Воспроизведение на машине с Node.js 18.19.0 и Python 3 (первый шаг скачает только восемь hash-pinned npm-архивов; npm install scripts не выполняются):

```sh
set -eu
SOURCE=/absolute/path/to/patched/OpenSearch-Dashboards-2.14.0
PATCH_DIR=/absolute/path/to/patches
WORK="$(mktemp -d)"
python3 "$PATCH_DIR/tests/prepare.py" --work "$WORK"
# До применения этот запуск намеренно завершается кодом 1:
node "$PATCH_DIR/tests/regression.cjs" "$WORK/fixtures" && exit 1
node "$SOURCE/scripts/security_backports/apply.cjs" "$WORK/fixtures"
node "$PATCH_DIR/tests/regression.cjs" "$WORK/fixtures"
node "$PATCH_DIR/tests/compatibility.cjs" "$WORK/original" "$WORK/fixtures"
node "$PATCH_DIR/tests/installer.cjs" "$SOURCE" "$WORK/fixtures" "$WORK/original"
node "$PATCH_DIR/tests/build-hook.cjs" "$SOURCE" "$WORK/original"
```

Для offline-проверки `prepare.py` принимает `--cache /path/to/tgz-directory`; имена файлов указаны в `tests/fixtures.json`. Проверка diff отдельно:

```sh
python3 patches/tests/verify-series.py 2.14.0.tar.gz /tmp/osd-series-check-new
```

Каталог назначения должен отсутствовать. Логи выполненных проверок и первичные JSON-записи advisories находятся в `evidence/`. Ревью дополнительно обнаружило квадратичность внешнего цикла URI-fallback на множестве уникальных валидных фрагментов в повреждённой строке. Патч 0004 устраняет и её; отдельный тест считает объём повторных замен, а не полагается только на время выполнения.

## Откат

Предпочтительно восстановить исходный архив и пересобрать артефакт с исходными зависимостями. Обратный `patch -R` удаляет source hooks и recipes, **но не отменяет уже изменённые node_modules**. Их необходимо восстановить чистой установкой в новом дереве; старые frontend bundles также требуют восстановления/пересборки. Не используйте откат только одного из четырёх патчей для production.
